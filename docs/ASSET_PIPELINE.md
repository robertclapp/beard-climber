# Beard Climber – retro 3D→pixel-art asset pipeline (prototype)

Historical asset-pipeline documentation from the source handoff. See
[DEVELOPMENT.md](../DEVELOPMENT.md) for the current private-repository workflow.

An original retro arcade climbing game where the hero climbs **giant beards**. All models
(beards, faces, climber, hazards) are low-poly geometry generated by Python in
Blender. They are rendered orthographically at arcade resolution (224x256, 32 px per
tile) and then snapped to each level's 16-colour palette, so they look like early-80s sprites.

Tested with **Blender 4.2.3 LTS**, headless, CPU only, using the **Workbench** engine
(flat lighting, material colours, anti-aliasing off). It uses only the stable `bpy` API, so the
same scripts should run on macOS Apple Silicon. A full build (5 levels + climber, including GIFs and MP4s) takes ~50 s.

## Files
| file | role |
|---|---|
| `common.py` | palette roles → materials, `MeshBuilder` (batches boxes/discs/spheres into one mesh), Workbench + ortho camera setup |
| `beard.py` | the whole tall level: tapering beard tip (`tip_end()`), beard tiles (strands, knots, theme holds, bald/slippery patch, decor), edge fringe, face at the top, and `mouth()` closed/open variants; stand-alone `.blend` export |
| `climber.py` | shared climber (seen from behind: beanie, hair, backpack), Empty-joint rig, eased 8-frame climb cycle + fall pose |
| `levels/*.py` | **one file per beard**: palette, hair style, tile weights, holds, mustache, headwear, hazard models, scene layout |
| `render_levels.py` | Blender: renders each whole level (tip→face) twice (mouth closed/open), plus climber, hazard, enemy and tile sprites, and saves `.blend`s, then runs `postprocess.py` |
| `pixfont.py` | 5x7 arcade bitmap font for the HUD, the text cues and the how-to screen |
| `sfx.py` | chiptune sound effects synthesised with numpy, written as WAVs, and muxed into the MP4 previews with ffmpeg |
| `postprocess.py` | Python 3 + Pillow: palette quantisation, optional Bayer dither, 1px outline, and the **level timeline** (class `Level`) that composes start/mid/top frames, the full-level strip, the scroll GIF, sheets and overviews |
| `run_all.sh` | one-shot rebuild |

## Run on a Mac
```bash
pip3 install pillow numpy                             # post-process uses system python3 + Pillow + numpy
brew install ffmpeg                                   # optional: MP4 previews with sound (else use --post-args --no-mp4)
BL=/Applications/Blender.app/Contents/MacOS/Blender
cd beardclimber
$BL -b --python render_levels.py                      # everything (~50 s)
$BL -b --python render_levels.py -- --levels viking   # one level
$BL -b --python beard.py -- --level pirate --rows 30  # just one level's .blend (beard tip -> face)
$BL -b --python climber.py                            # just the climber .blend
python3 postprocess.py --dither                       # re-run only the 2D look, no Blender
# or: BLENDER=$BL ./run_all.sh
```
On Linux, use the same commands with the path to your Blender binary.

## Knobs
* `render_levels.py --`: `--levels a,b`, `--cols 6`, `--rows N` (overrides every level's beard length), `--seed N`,
  `--width 224 --height 256`, `--ppu 32`, `--sprite 48` (hazard cell), `--climber-sprite 72`, `--no-post`, `--post-args "--dither"`.
* `postprocess.py`: `--dither` (4x4 ordered Bayer, off by default), `--no-outline`, `--scale 4`, `--levels`, `--no-mp4`.
  Hard hat: `HAT_HITS`, `AIMED_HITS`, `HAT_THROW_AT`, `HIT_R`.
  Timeline constants at the top of the `Level` section: `SCROLL_FRAMES`, `END_FRAMES`, `SPIT_AT`, `FALL_SPEED`, `EMERGE`.
* Climber: `climber.SCALE` (1.5 gives ~59 px tall). `climb_pose()` / `fall_pose()` return joint angles in degrees.

## Level config (one dict per `levels/<name>.py`)
| key | meaning |
|---|---|
| `palette` | 16 colours by role (`black white skin skin_shade lips shirt pants cap bg hair1..hair4 acc1..acc3`, extra `acc4` allowed) |
| `rows` | beard length in tiles (the climb). Wizard 26, Lumberjack 22, Viking 24, Santa 20, Pirate 24 |
| `tip`, `taper_rows` | tip silhouette `point` / `ragged` / `round` / `fork` (+ `fork_x`) / `braids`, and how many rows it tapers over |
| `style`, `wave_amp`, `wave_period`, `strand_pattern`, `braid_cols` | hair look (`straight` / `wavy` / `braided` / `fluffy`) |
| `tile_weights`, `holds`, `decor` | tile mix, theme hand-holds, decor type |
| `mustache`, `brows`, `cheeks`, `eyepatch`, `headwear()` | face at the top |
| `hazards`, `enemy`, `fx` | hazard builders `(name, fn)`, optional cross-screen enemy `(name, fn(mb, frame))`, `sparkles` / `snow` |
| `spawn` | where hazards leave the mouth, as (dx, dz) from the mouth centre |
| `throw_period`, `drift` | frames between throws; max sideways drift per frame (throws alternate left/right) |
| `start_x`, `start_z`, `end_x` | climber start position at the tip, and his x at the top |
| `climber_roles` | climber colours (`beanie`, `hardhat`, `hardhat_shade`) as aliases of existing palette roles, so a level stays at 16 colours |
| `powerup` | `tangled_at`: the climb frame at which he reaches the hard hat tangled in the beard |
| `enemy_path` | frames and screen height of the enemy's pass (Santa's reindeer) |

## Design notes
* **One tall level:** the climb starts at the beard's tip, which hangs over open background at the bottom. Then come `rows` rows
  of beard, and the face (mouth, mustache, nose, eyes, hat) appears only at the very top. Blender renders the whole level as one
  tall image, and every game frame is a crop of it. Everything shares one orthographic pixel grid, so the crops are pixel-exact.
* **Hazards come out of the mouth:** every hazard is spawned at the mouth (`spawn`) every `throw_period` frames. It sits in the
  open mouth for `EMERGE` frames, then falls at a constant speed with alternating sideways drift, bouncing off the beard edges.
  The mouth swaps from closed to open from 2 frames before a throw until the hazard leaves it.
  **When the face is off-screen above, hazards just fall into view from the top edge.** That is the same simulation: they were
  thrown from the mouth far above, so no hazard ever appears at a random spot.
* **The camera follows the climber.** He starts in the lower-middle of the screen and drifts down to the lower part of the screen
  as the camera reaches the top (the camera is clamped at the hat brim), so the open mouth and the falling hazards stay visible.
* The **mouth** is a separate object in each `<level>.blend` (`mouth_closed` / `mouth_open`), ready to animate.

## Hard hat power-up
* **Where it comes from:**
  * A hard hat sits **tangled in a hand-hold** (a knot of strands) a little above the start, marked with a distinct blinking
    white/gold 4-point sparkle. The climber picks it up when he reaches it (`powerup.tangled_at`).
  * The mouth also, rarely, **throws a hard hat as a 'good' item** (`HAT_THROW_AT`, near the end of the demo).
    It uses the same sparkle and can be caught.
* **Wearing it:** a yellow hard hat (modelled in Blender, `climber.build_hardhat`) replaces the beanie on the sprite.
* **It absorbs the next 3 hits** (`HAT_HITS`), with no knock-back and no life lost. On each hit:
  * the hat **flashes white** (a hat-only mask render) and shows one more **crack** (3 sprite states: intact, cracked, badly cracked);
  * the hazard bounces off;
  * the HUD loses a pip; a `CLINK!` cue appears with the `clink.wav` sound.
* **On the 3rd hit** the hat **pops off** and tumbles away, with a `POP!` cue and `pop.wav`. A hit without a hat shows the hurt pose and `OUCH!`.
* **HUD:** top-left `HAT` plus 3 hard-hat pips (filled = hits left, outline = used). It is shown only while a hat is worn.
* **In the demo timeline** a few throws are back-solved to meet the climber, so every level shows pickup, 3 absorbed hits and the
  pop. All other throws are steered to miss him. They are still thrown from the mouth.
* **Sound:** `out/sfx/*.wav` (pickup, clink, pop, hurt, spit, spit_hat). `out/<level>/sfx_events.json` lists the frame and time
  of every cue, and `scroll_sfx.mp4` is the scroll preview with the sounds mixed in. GIFs are silent.
* **How-to screen:** `out/howto.png` / `howto_x4.png` is an attract-mode card built from the real sprites. It covers climbing,
  dodging what the mouth spits, the hard hat (3 hits + HUD pips), grip knots vs bald patches, and the controls.

## Optional level hooks
* `face_extra(mb, cx, eye_z, cols)` - extra face geometry drawn after the eyes (Grandpa's glasses).
* `forced_tiles: {(col, row): kind}` - hand-placed tiles (Grandpa's tutorial bald patch above the start column); applied
  after the random pick, so other levels' tile maps are unchanged.

## Adding a new beard level
1. Copy `levels/viking.py` to `levels/dwarf.py` (for example).
2. Edit the `palette`. Keep the role names: `black white skin skin_shade lips shirt pants cap bg hair1..hair4 acc1..acc3`
   (extra roles such as `acc4` are fine, but stay at 16 unique colours in total). `hair1` is darkest and `hair4` lightest.
3. Set `rows`, `tip`, `taper_rows`, `start_x`, `spawn`, and `throw_period`. Pick `style`, `mustache`, `holds`, and `decor`. Write a `headwear(mb, cx, z, cols)` function and 3-4 hazard functions `fn(mb)`
   that build around the origin (~0.8 units max) using `mb.box / mb.disc / mb.sphere / mb.bar` with palette role names.
4. Add `"dwarf"` to `ORDER` in `levels/__init__.py` and run `render_levels.py -- --levels dwarf`.
New hold types go in `beard.hold_prop()`, and new decor types in `beard.decor()`.

## Outputs (`out/`)
* `levels_overview.png` shows every level's top frame (mouth open, spitting). `levels_start_overview.png` shows every start frame.
  `levels_hardhat_overview.png` shows every level's first absorbed hit.
* `howto.png` / `howto_x4.png`: the how-to-play screen. `sfx/*.wav`: the sound effects.
* `<level>/`:
  * `frame_start_x4.png`: beard tip, climber starting, hazards falling in from above.
  * `frame_mid_x4.png`: the middle of the beard.
  * `frame_top_x4.png`: the face, with the mouth open spitting a hazard.
  * Each frame also has a 1x `.png`.
  * `level_strip.png` (x2) + `level_strip_1x.png`: the whole climb, tip to face.
  * `scroll.gif` (x2, about 7.7 s, silent) and `scroll_sfx.mp4` (with sound): the pan from the tip up to the face, with the
    hard-hat pickup, 3 absorbed hits and the pop. It ends with the mouth spitting a hazard and then throwing a hard hat.
  * `frame_hardhat_pickup_x4.png`, `frame_hardhat_hit_x4.png` (flash + `CLINK!` + 2 pips),
    `frame_hardhat_pop_x4.png`, `frame_hardhat_throw_x4.png` (mouth throws a hard hat).
  * `hardhat_states_x4.png` (beanie / intact / cracked / badly cracked), `hardhat_items_x4.png` (spin frames + tangled), `sfx_events.json`.
  * `mouth_closed_open_x4.png`: a close-up pair of the two mouth states.
  * `tiles(_x4).png`, `hazards(_x4).png`, `hazards_on_bg_x4.png`, `<level>.blend`, `raw/` (layers; not in the zip).
* `climber/`: `climber_sheet(_x4).png`, `climber_fall(_x4).png`, `climber_cycle.gif`, `climber.blend`.

## Limitations
* Flat, front-on orthographic look. Depth comes only from the palette and shape design, not from lighting.
* The rig uses Empties, not an Armature (no skinning). The climber's palette colours are set per level.
* This is an asset pipeline plus **scripted previews**, not a playable game. There is no input or game loop. Hits and the hard
  hat are simulated in a fixed demo timeline (aimed throws), and the how-to screen is a still image.
  The scroll speed is a preview, so the climb cycle "slides" a little relative to the beard.
* Wizard sparkles and Santa's snow are drawn as pixels in post-processing, not rendered in 3D.
* Hazard "falling" frames are 90° spins in the picture plane, not hand-drawn tumbles.
* Faces are generic blocky archetypes (no likenesses).


## Playable web game (World 1-1 Grandpa + the Wizard)
`web/index.html` is a self-contained web game: **World 1-1 Grandpa** (`levels/grandpa.py`: the unfailable tutorial
level, first for new players) and the **Wizard** (World 3 boss, unlocked by cheering Grandpa up), a world select,
desktop/tablet letterboxing and Poki-portal groundwork (no network). The Wizard climb is the original Wizard level
(touch + keyboard, WebAudio, hard hat, sneeze event), with a kid-friendly story (opening cinematic,
intro, ending, parachute bonus), a character creator for the hero Pip (`web/pip.py`, layered key-colour renders). A coin shop (coins earned in-game only: hats, outfits, packs, parachutes, consumable boosts, giant-themed sets) a 1.6x longer beard with rare shelter tangles and a height-ramped difficulty, all tunable in the `T` block. See `web/README.md` for controls, rebuild
and test instructions; screenshots and a bot-played GIF are in `web/shots/`.
Note: the Wizard level's bald-patch weight was raised (0.035 -> 0.07) so the game has more
obstacles; the scripted previews in `out/wizard/` were rendered before this change.
